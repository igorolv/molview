## 2. Цель и жёсткие ограничения

Получить **самостоятельное приложение под Windows** с окном, которое делает то же
самое, что веб-версия. Это требование школы: проект должен быть на компилируемом
языке.

Ограничения обсуждены с заказчиком и **не подлежат пересмотру**:

1. **Ни одной внешней библиотеки.** Только `<windows.h>`, `<gdiplus.h>` и
   стандартная библиотека C++. Никаких raylib, Qt, SDL, nlohmann/json, stb.
   Причина: проект оценивает учитель информатики, и на вопрос «что здесь твоё?»
   должен быть исчерпывающий ответ.
2. **Разбор JSON пишется свой** — примерно 150 строк рекурсивного спуска.
   Файлы данных простые: объекты, массивы, строки, числа, `true`/`false`/`null`.
3. **Тулчейн — только w64devkit** (портативный zip с g++, make, gdb; без
   установщика, без прав администратора, без реестра). CMake нет и не нужен:
   сборка обычным `Makefile`.
4. **Только Windows** — это согласовано.
5. Сборка выдаёт **один статический .exe без DLL рядом**.

2. **Немедленно проверить, что GDI+ собирается.** Это главный технический риск

```cpp
// probe.cpp
#define NOMINMAX
#define UNICODE
#include <windows.h>
#include <gdiplus.h>
#include <cstdio>
int main() {
    Gdiplus::GdiplusStartupInput in;
    ULONG_PTR token;
    Gdiplus::Status s = Gdiplus::GdiplusStartup(&token, &in, nullptr);
    std::printf("GdiplusStartup -> %d\n", (int)s);
    Gdiplus::GdiplusShutdown(token);
    return 0;
}
```

```
g++ -std=c++17 probe.cpp -o probe.exe -lgdiplus && probe.exe
```

Ожидается `GdiplusStartup -> 0`.

**Если не собирается**, типичные причины и лечение:
* конфликт макросов `min`/`max` → `#define NOMINMAX` до `<windows.h>`;
* `gdiplus.h` требует, чтобы `<windows.h>` был включён раньше;
* у некоторых сборок MinGW нужно `#include <objidl.h>` перед `<gdiplus.h>`;
* порядок библиотек в командной строке: `-lgdiplus` **после** объектных файлов.

**Если и это не помогло** — переходить на запасной план, см. раздел 10.
Не начинать порт рендера, пока проба не прошла.

## 6. Ядро: что важно не переврать

Ниже — те решения, которые неочевидны из кода и которые легко испортить
«улучшениями». Все константы приведены точно.

### 6.1. Векторы

В C++ определить операторы: `a + b`, `a - b`, `a * k`, `dot`, `cross`, `length`,
`normalize`. Выражения станут заметно чище, чем в оригинале, — это нормально
и приветствуется. Матрица 3×3 — `std::array<double, 9>` по строкам.

Нужны: поворот вокруг оси (формула Родрига), минимальный поворот из вектора в
вектор, построение ортонормированного базиса по двум векторам, совмещение пары
направлений, собственные векторы симметричной матрицы 3×3 методом Якоби
(для разворота молекулы по главным осям).

### 6.2. Неявные атомы водорода

Обычный атом: берётся наименьшая стандартная валентность, которой хватает на
уже имеющиеся связи. Поправка на заряд: у B, C, Si, Ge, Sn, Al, Be, Mg
валентность уменьшается на `|заряд|`, у остальных увеличивается на заряд.

**Ароматический атом — особое правило, без него ломается кофеин.** Кратности
связей в кольце до расстановки формы Кекуле не определены. Считаем так:
каждая связь кольца даёт единицу, плюс единица за участие в π-системе, и
используется **только низшая** валентность элемента:

```
бензол   c:  σ=2, π=1 → 4 − 3 = 1 атом H
толуол   c:  σ=3, π=1 → 4 − 4 = 0
пиридин  n:  σ=2, π=1 → 3 − 3 = 0
кофеин   n:  σ=3, π=1 → 3 − 4 < 0 → 0     ← без низшей валентности вышло бы 1
фуран    o:  σ=2, π=1 → 2 − 3 < 0 → 0
```

### 6.3. Длина связи

Сумма ковалентных радиусов минус укорочение, зависящее от кратности
**непрерывно** (нужны дробные порядки 1,5 и 1⅓):

```
o = clamp(order, 1, 3)
укорочение = o <= 2 ? 0.19*(o-1) : 0.19 + 0.13*(o-2)
```

### 6.4. Неподелённые пары

```
НЭП = round( (валентные_электроны − заряд − Σ кратностей) / 2  −  0.001 )
```

Вычитание `0.001` перед округлением принципиально: у ароматических атомов
получается ровно «половинка» пары, означающая пару, ушедшую в π-систему,
и её надо отбросить вниз, а не вверх. Иначе у пиррола азот получит лишнюю пару
и станет sp³ вместо sp². В C++ `std::round(0.5)` даёт 1 — то же поведение,
что у `Math.round`, так что приём переносится дословно.

### 6.5. Делокализация (`resonance`)

Для каждого атома: сгруппировать **концевых** соседей (степень 1, не водород)
по элементу. Если в группе больше одного соседа и кратности или заряды
различаются — усреднить и кратности, и заряды, пометить связи как
делокализованные.

Правило обязано срабатывать для нитрат-, нитрит-, карбонат-, сульфат-,
фосфат-, ацетат-ионов, нитрогруппы, озона, азотной кислоты — и обязано
**не срабатывать** для уксусной кислоты и метилформиата, где второй кислород
несёт водород или углеродный заместитель (степень 2, значит не концевой).
Ароматические связи пропускать.

### 6.6. Теория Гиллеспи (`vsepr`) — сердце программы

Энергия отталкивания электронных групп, размещённых на единичной сфере:

```
E = Σ (wᵢ · wⱼ) / rᵢⱼ⁶        rᵢⱼ — расстояние по хорде
```

Веса (откалиброваны по справочным углам H₂O, NH₃, H₂C=O — **не менять**):

```
одинарная связывающая пара   w = 1.00
прибавка за кратность        w += 0.18 * (order − 1)
неподелённая пара            w = 1.45
показатель степени           n = 6
```

Порядок групп в массиве весов: сначала связи в порядке соседей, потом пары.
Результат возвращается в том же порядке.

**Стерическое число ≤ 4 — свободная минимизация:**
* 24 запуска из случайных начальных положений;
* градиентный спуск: сила `F_i = Σ_j n·wᵢ·wⱼ·(pᵢ−pⱼ)/d^(n+2)`, берётся только
  касательная к сфере составляющая `F − p·(F·p)`, точка смещается и
  нормируется;
* первый проход: 3000 шагов, начальный шаг 0.3, затухание ×0.9985 за шаг;
* второй (полировка): 600 шагов, начальный шаг 0.02, затухание ×0.999;
* берётся конфигурация с наименьшей энергией.

**Генератор случайных чисел — свой, детерминированный** (иначе одна и та же
молекула будет каждый раз выглядеть иначе). Линейный конгруэнтный:

```cpp
uint32_t s = seed;                       // seed = 0x9e3779b9 + attempt*7919 + n*104729
double next() { s = s * 1664525u + 1013904223u; return s / 4294967296.0; }
```

Переполнение `uint32_t` в C++ определено и совпадает с `>>> 0` в JavaScript,
так что последовательность будет идентичной.

Начальная точка: `u = rnd()*2−1`, `phi = rnd()*2π`, `r = sqrt(1−u²)`,
`(r·cos φ, r·sin φ, u)`.

**Стерическое число 5–7 — точный шаблон плюс перебор.** Свободная минимизация
даёт мелкие искажения там, где симметрия требует ровно 90° и 120°, поэтому
берётся точный шаблон геометрии, а распределение групп по его вершинам
выбирается перебором **всех перестановок** по минимуму той же энергии
(7! = 5040 — это мгновенно). Именно перебор, а не таблица: правила
«пара уходит в экватор бипирамиды» и «две пары в октаэдре становятся транс»
должны выводиться, а не задаваться. Шаблоны:

```
СЧ=5  тригональная бипирамида: 3 экваториальные (120° в плоскости XY) + (0,0,±1)
СЧ=6  октаэдр: (0,0,±1), (±1,0,0), (0,±1,0)
СЧ=7  пентагональная бипирамида: 5 в плоскости XY через 72° + (0,0,±1)
```

**Канонизация.** После получения направлений привести к воспроизводимой
ориентации: повернуть так, чтобы первая группа смотрела вдоль +Z, затем
повернуть вокруг Z так, чтобы вторая легла в плоскость XZ.

**Кэширование.** Результат кэшировать по строке из весов — иначе минимизация
будет гоняться для каждого атома заново. Ключ: веса, отформатированные с
4 знаками после запятой, через разделитель.

### 6.7. Поиск циклов (`rings`)

Для каждой связи между тяжёлыми атомами: мысленно удалить её и найти кратчайший
путь между концами обходом в ширину. Путь плюс связь — наименьший цикл через
эту связь. Убрать дубликаты по набору атомов, отсортировать по длине, отобрать
независимые — их столько, сколько даёт цикломатическое число
`рёбра − вершины + компоненты`.

Цикл ароматический, если ароматичны все его связи.

### 6.8. Построение координат (`build3d`)

**Сначала укладываются циклы по шаблонам.** Конденсированные системы
объединяются в группы по общим атомам.

* Система, где какой-то атом входит в **три и более** цикла (адамантан,
  норборнан) — шаблоном не укладывается вообще, её целиком строит обход графа,
  а расхождения потом устраняет релаксация.
* Все атомы имеют СЧ ≤ 3 или ароматичны → плоская укладка в плоскости z=0:
  первое кольцо правильным многоугольником радиуса `L / (2·sin(π/n))`,
  последующие пристраиваются по общей связи. Центр нового кольца — от середины
  общей связи наружу от уже построенной части на расстояние апофемы.
* Иначе — только первое кольцо:
  * 6 атомов — «кресло»: радиус `0.948·L`, отклонение по оси `±0.162·L`
    через один. При `L = 1.54 Å` даёт связь 1,54 Å и угол 111,5°;
  * 5 атомов — «конверт»: правильный пятиугольник, пятый атом поднят на `0.28·L`;
  * 4 атома — квадрат со складкой `±0.05·L`;
  * иначе — плоский многоугольник.

**Затем наращивание обходом в ширину.** Для очередного атома известны
направления его групп в собственной системе координат; нужен поворот,
совмещающий их с уже размещёнными соседями:

* **ноль размещённых** — единичная матрица (корень обхода: тяжёлый атом с
  наибольшим числом соседей);
* **один размещённый** — поворот определён с точностью до вращения вокруг связи.
  Это вращение и есть конформация: перебрать **36 положений** и выбрать то, при
  котором сумма `1/d⁴` до всех уже построенных атомов минимальна. Так сама собой
  получается заторможенная конформация этана и анти-конформация бутана;
* **два и более** — совмещать **по биссектрисе и нормали**, а не по паре
  направлений напрямую. Это важно: когда реальный угол в цикле отличается от
  идеального (циклопропан — 60° против 109,5°), совмещение по паре
  перекашивает всё окружение, а по биссектрисе — остаётся симметричным.
  Пару для нормали брать с наибольшим углом между направлениями.

**Релаксация** — 600 итераций, за итерацию:

| Что | Целевое значение | Коэффициент |
|---|---|---|
| длины связей | сумма радиусов с поправкой | 0.85 |
| расстояния 1–3 (через атом) | по теореме косинусов из идеального угла | 0.35 |
| несвязанные дальше 3 связей | не ближе 2.4 Å | 0.25 |

Смещение применяется с общим множителем 0.6. **Неподвижны только те атомы,
которые уложены по шаблону кольца** — не все атомы циклов. Мостиковые системы
шаблоном не укладываются, и релаксация обязана их править. Ограничения 1–3
пропускаются, если все три атома неподвижны.

**Разворот молекулы.** По главным осям матрицы ковариации положений тяжёлых
атомов (метод Якоби), затем фиксированный наклон: поворот вокруг X на −0.32 рад
и вокруг Y на +0.42 рад — чтобы объём читался лучше, чем строго анфас.

### 6.9. Разбор (`analyze`)

Порядок: делокализация → суммы кратностей → неподелённые пары и стерические
числа → направления групп → поиск циклов → построение координат → разбор
атомов → валентные углы → дипольный момент.

**Привязка экспериментальных углов.** В справочнике для одной подписи может быть
несколько значений: в гексафториде серы «F–S–F» относится и к двенадцати углам
по 90°, и к трём по 180°. Каждое справочное значение привязывается к тому ещё
не занятому углу, предсказание для которого к нему ближе всего. Подпись угла
нормализуется: внешние атомы сортируются по алфавиту (`H-C-Cl` → `Cl-C-H`).

**Дипольный момент** — качественная оценка: сумма векторов диполей связей
(единичный вектор от менее электроотрицательного к более, умноженный на
разность ЭО) плюс вклад неподелённых пар (`0.50` вдоль направления пары),
всё умножается на `1.25`. Полярной считается молекула при `|μ| > 0.06`.
**Число в дебаях не выводить** — расчёт на это не претендует; в интерфейсе
показывается качественная оценка, а числовое значение берётся из справочника.

### 6.10. Разбор запроса (`database`)

Порядок попыток строго такой: **точное название или синоним → брутто-формула →
вхождение в название → SMILES**. Формула идёт раньше SMILES специально: на
запрос `C2H6O` программа должна показать **оба изомера**, а не молча разобрать
строку как SMILES.

Брутто-формула сравнивается по каноническому ключу состава (элементы по
алфавиту с количествами). Порядок элементов в формуле для показа зависит от
того, есть ли углерод: органика — система Хилла (сначала C, потом H, потом
остальные по алфавиту), неорганика — электроотрицательностный ряд IUPAC
(SO₂, PCl₃, NH₃, XeF₂; кислород и фтор в конце). У кислородсодержащих кислот
водород по традиции выносится вперёд (H₂SO₄, HNO₃), а OH⁻ и HCN заданы явными
исключениями. Подробности — в `formulaOrder` (molview/src/chem/formula.ts).

## 7. Проверка (обязательная часть)

### 7.1. Сверка с эталоном

`tests/selftest.cpp` загружает `data/reference.json` и для каждой из 89 молекул
сравнивает:

| Величина | Допуск |
|---|---|
| брутто-формула, суммарный заряд | точно |
| число атомов, связей, циклов | точно |
| для каждого атома: элемент, σ-связи, НЭП, стерическое число, тип AXE, гибридизация, обе геометрии | точно |
| кратность связи, признаки ароматичности и делокализации | точно |
| длина связи | 0.01 Å |
| валентный угол (`predicted` и `actual`) | 0.05° |
| признак полярности | точно |

Строки `axe` и `hybrid` содержат юникодные подстрочные и надстрочные знаки
(`AX₄E₂`, `sp³d²`) и должны совпадать побайтово — это заодно проверяет, что
с кодировкой всё в порядке.

Эталон пересоздаётся из оригинала командой `npm run reference` в каталоге
`molview` (скрипт `scripts/dump-reference.ts`). Делать это надо только если
в оригинале осознанно что-то менялось.

**Координаты не сравниваются** и в эталон не выгружены: минимизация энергии
может прийти к тому же самому минимуму, повёрнутому в пространстве. Все
сравниваемые величины от поворота не зависят.

Нумерация атомов детерминирована порядком разбора SMILES и должна совпасть.

**Если какая-то молекула разошлась**, вероятные причины по убыванию частоты:
1. ошибка в разборе SMILES (проверяется отдельно по брутто-формулам);
2. не сработало или лишний раз сработало правило делокализации;
3. правило неявных водородов для ароматических атомов;
4. округление в расчёте неподелённых пар (вычитание 0.001);
5. **вырожденный минимум** — если у двух конфигураций энергия совпадает с
   точностью до 1e-12, мельчайшая разница в вычислениях с плавающей точкой
   может выбрать другую. Признак: расходятся только углы, причём набор значений
   тот же, а распределение по парам другое. Лечение: сравнивать
   отсортированный набор углов при данном центре, а не каждую пару отдельно.

## 8. Рендер: соответствие Canvas 2D → GDI+

Рендер устроен так: перспективная проекция считается вручную, объём создаётся
сортировкой примитивов по глубине (алгоритм художника). От GDI+ нужны только
заливки, градиенты, пути и текст.

| Canvas 2D | GDI+ |
|---|---|
| `createRadialGradient(x0,y0,r0,x1,y1,r1)` | `PathGradientBrush` по окружности; `SetCenterPoint` задаёт смещённый центр блика, `SetCenterColor` / `SetSurroundColors` — цвета |
| `createLinearGradient(x0,y0,x1,y1)` | `LinearGradientBrush`; несколько остановок — `SetInterpolationColors` |
| `beginPath` / `moveTo` / `lineTo` / `closePath` / `fill` | `GraphicsPath` + `FillPath` |
| `bezierCurveTo` (лепестки орбиталей) | `GraphicsPath::AddBezier` |
| `arc` | `AddEllipse` / `AddArc` |
| `setLineDash` | `Pen::SetDashPattern` |
| `shadowBlur` (свечение) | эмулировать несколькими обводками с растущей толщиной и падающей прозрачностью |
| `globalAlpha` | альфа в `Color(a, r, g, b)` |
| `measureText` | `Graphics::MeasureString` |
| `fillText` | `Graphics::DrawString` |
| сглаживание | `SetSmoothingMode(SmoothingModeAntiAlias)`, для текста `SetTextRenderingHint(TextRenderingHintAntiAliasGridFit)` |

Обязательно: `GdiplusStartup` при запуске, `GdiplusShutdown` при выходе.
Рисовать в `Bitmap` в памяти, затем выводить одним `BitBlt` — иначе будет
мерцание.

На тёмном фоне ClearType даёт цветную бахрому, поэтому для текста именно
`TextRenderingHintAntiAliasGridFit`, а не `ClearTypeGridFit`.

Что должно быть перенесено из рендера: шары с бликом и ободком, связи с
поперечным градиентом, кратные и пунктирные (делокализованные) связи,
затуманивание дальних объектов, дуги валентных углов с подписями и разведением
подписей, облака неподелённых пар, лепестки гибридных орбиталей, стрелка
дипольного момента, подписи элементов и зарядов, анимация появления, три стиля
модели (шаростержневая, объёмная, каркасная).

## 9. Интерфейс

Раскладка как в веб-версии: слева каталог, в центре сцена, справа панель
разбора, снизу по центру панель инструментов.

**Единственный нативный контрол — поле ввода `EDIT`** для строки поиска.
Самому писать курсор, выделение, Ctrl+V и работу с раскладкой — яма времени
без всякой пользы для проекта. Затемняется через `WM_CTLCOLOREDIT`
(`SetTextColor`, `SetBkColor`, вернуть кисть фона), шрифт задаётся `WM_SETFONT`.

Всё остальное рисуется самостоятельно через GDI+ с ручной проверкой попадания
мыши: каталог с прокруткой, кнопки панели инструментов, панель разбора,
таблица углов, подсказки поиска, окно справки.

Сообщения, которые надо обработать: `WM_PAINT`, `WM_SIZE`, `WM_MOUSEMOVE`,
`WM_LBUTTONDOWN`/`WM_LBUTTONUP`, `WM_MOUSEWHEEL`, `WM_LBUTTONDBLCLK`,
`WM_KEYDOWN`, `WM_COMMAND` (от поля ввода), `WM_TIMER` или таймер высокого
разрешения для анимации 60 кадров в секунду.

Приоритет, если время поджимает: сцена важнее панели, панель важнее подсказок
поиска и окна справки.

## 10. Запасной план, если GDI+ не заработает

Написать собственный растеризатор:

* рисовать сцену в массив пикселей `uint32_t` **в двойном разрешении**,
  затем усреднять блоками 2×2 — это даёт сглаживание без единой строчки
  специальной логики;
* заливка круга с градиентом, выпуклого четырёхугольника с интерполяцией
  цвета по вершинам, отрезка — по 20–40 строк каждая;
* кривые Безье лепестков разбивать на ломаную и заливать как многоугольник;
* готовый буфер выводить через `StretchDIBits`;
* **текст** рисовать обычным GDI поверх: создать `DIB section`, выбрать её в
  memory DC, и вызывать `DrawTextW` с `SetBkMode(TRANSPARENT)`. Кириллица
  работает с любым системным шрифтом.

Это примерно 400 строк дополнительно, зато зависимость остаётся только от
`gdi32`. На защите «я написал собственный растеризатор» звучит даже сильнее.

## 11. Соглашения

* **C++17**, предупреждения включены: `-Wall -Wextra`.
* **Комментарии и все строки интерфейса — по-русски**, как в оригинале.
  Комментарии объясняют *почему*, а не *что*: код и так видно.
* Исходники в UTF-8. Собирать с `-finput-charset=UTF-8 -fexec-charset=UTF-8`.
  Для консольного вывода в начале `main` вызвать `SetConsoleOutputCP(CP_UTF8)`.
  Для Windows API использовать широкие строки (`UNICODE`, `-W` функции) и
  конвертировать UTF-8 → UTF-16 через `MultiByteToWideChar`.
* Именование: типы `PascalCase`, функции и переменные `camelCase`,
  константы `UPPER_SNAKE` — как в оригинале, чтобы соответствие было очевидным.
* Заголовки самодостаточны, `#pragma once`.
* Никаких «улучшений» алгоритмов по ходу дела. Если что-то в оригинале выглядит
  странно — почти наверняка это осознанное решение, объяснённое в записке.
  Сначала свериться с эталоном, потом обсуждать.

## 13. Чего делать не надо

* Не переносить веб-специфику: анимацию заголовков, всплывающие подсказки
  автодополнения можно упростить.
* Не добавлять новых молекул в базу — она общая с оригиналом, и любое
  расхождение сломает сверку с эталоном.
* Не менять калибровочные константы (веса групп, коэффициенты релаксации,
  масштаб диполя) — они подобраны численно, и эталон снят именно с ними.
* Не пытаться воспроизвести двугранные углы и конформационный анализ: этого
  нет и в оригинале.
* Не браться за комплексные соединения — для них нужна теория кристаллического
  поля, это выходит за рамки метода Гиллеспи.
